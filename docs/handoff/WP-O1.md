# Übergabe WP-O1 (Ingest-Automat und Worker-Befehl)

Stand 07.11.2026, Branch `wp-O1` (aufgesetzt auf `main` mit D2, Commit d356350). Gate: `scripts/ci.sh` mit `TEST_DB_NAME=labhub_o1`, Ergebnis siehe unten. Kein Reviewer-Lauf; empfohlen (Schwerpunkte: Lease-/Fail-SQL in `JobService`, Zeilensperre im Ingest-Automaten, Signalbehandlung im Worker).

## Umgesetzt
- **Migration `017_jobs_priority`** (Kern, `JobMigrations.swift`, eine Zeile in `HubMigrations.all`): `jobs.priority integer NOT NULL DEFAULT 0`, `jobs.last_error` (Code, max. 64 Zeichen), Index `jobs_claim`; `schema_version` 15 -> 17 (016 ist die DMS-Modulmigration). Expand-only, Revert vorhanden und getestet. `failed_permanent` ist nur ein neuer Textwert von `jobs.state`. Rollout: erst migrieren, alte Worker vorher beenden (alte Abfrage `state <> 'done'` würde `failed_permanent` wieder abholen).
- **`JobService`** (`Services.swift`): `enqueue(priority:)`, `claim(kinds:)` (Reihenfolge `priority DESC, run_at, created_at`, nie Jobs mit `attempts >= maxAttempts`; abgelaufene Lease bei erschöpften Versuchen wird im Claim `failed_permanent` = Absturzschleifen-Schutz), `fail(code:retryAfterSeconds:permanent:)` (nur Besitzer, nach 3 Versuchen oder `permanent` Quarantäne), `release` (zählt den Versuch nicht mit), `ClaimedJob.attempts`. Alle Zeiten `now()` der Datenbank; jede Wiederholung eines Übergangs ist ohne Wirkung.
- **Worker** (`Worker/JobWorker.swift`, `Worker/WorkerCommand.swift`): `App worker --kinds a,b [--lease-seconds 60] [--poll-ms 1000] [--retry-backoff-seconds 5]`, eigener Befehl ohne HTTP-Server, in `configure` registriert. Lease-Erneuerung alle Lease/3; verlorene Lease bricht den Handler ab und schreibt nichts mehr. SIGTERM/SIGINT: Handler wird abgebrochen (kooperativ, `Task.cancel`), Lease freigegeben, Exit 0. Fehler: exponentieller Abstand, `PermanentJobError` = sofort Quarantäne. Unbekannte Arten in `--kinds` beenden den Start (Exit 1); die Handler-Registry (`WorkerHandlers.registry`) ist leer bis auf die Diagnose-Art `worker.selftest` (nur mit `WORKER_ENABLE_SELFTEST=1`). **O2 trägt `dms.ocr` dort ein.**
- **Ingest** (`Modules/DMS/DMSIngest.swift`): Migration `dms_017_ingest` (Tabellen `dms_ingest_items`, `dms_ingest_transitions`, Schlüssel `(ingest_item, state)`, zusammengesetzter Mandanten-Fremdschlüssel auf `dms_documents`). Zustände `received -> stored -> hashed -> ocr_queued -> ocr_done -> classified -> done`, `failed_retryable|failed_permanent` mit `error_code` und `resume_state`. `advance` (Zeilensperre; erreicht/überschritten = No-op, Überspringen oder aus Fehler = 409 `conflict`), `fail`, `retry` (manuell, zurück auf letzten guten Zustand). Upload (D2) legt in derselben Transaktion ein Item an (Quelle `upload`, Zustand `hashed`) plus Audit `dms.ingest.received`.
